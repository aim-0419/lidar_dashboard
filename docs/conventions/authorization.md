# 권한 정책

이 문서는 대시보드 API와 화면에서 사용하는 역할별 접근 범위를 정의합니다.

> 최종 업데이트: 2026-09-03

## 역할

| 역할 | 설명 |
| --- | --- |
| `SUPER_ADMIN` | 이벤트 처리 상태·변경 사유, 사용자 계정, 관제 설정, 장비 제어와 테스트 기능을 관리하는 최고관리자 |
| `MANAGER` | 관제 현황·이벤트 이력을 조회하고 본인 계정 정보만 관리하는 일반 관리자. 이벤트 처리 상태·변경 사유는 수정 불가 |

## 이벤트 로그 운영 정책

- 2026-09-03 결정: 이벤트 상태·변경 사유 저장은 `SUPER_ADMIN`만 허용하는 기존 정책을 유지합니다. `MANAGER`에게 편집 권한을 확대하지 않습니다.
- `MANAGER`는 이벤트 목록·상세·검색·필터와 현재 관리 상태를 조회합니다. 상태 선택, 변경 사유 입력, 저장 UI는 제공하지 않습니다.
- `SUPER_ADMIN`는 관리 상태(`NEW`, `CONFIRMED`, `RESOLVED`, `FALSE_ALARM`)를 변경하거나, 상태를 유지하면서 변경 사유만 추가할 수 있습니다.
- 관리 상태와 변경 사유에 변경이 없으면 저장 버튼을 비활성화합니다. 공백만 입력한 사유는 변경으로 취급하지 않습니다.
- 변경 사유 입력은 기존 이력 수정이 아니라 새로운 사유 기록의 추가입니다. 처리자·처리 시점·상태 변경 및 사유는 이벤트 처리 이력에 남깁니다.
- 이 기능은 DB의 이벤트 관리 상태·처리 이력을 변경합니다. 차단기·스피커·전광판에 명령을 보내거나 물리 장비를 복귀시키지 않습니다.
- 라이다에서 수신한 `situation-ended`와 관제자가 지정하는 관리 상태는 구분합니다. 이 정책은 관제자의 수동 편집 권한에 대한 기준입니다.

### API 및 화면 검증 기준

| 대상 | MANAGER | SUPER_ADMIN | 미인증 |
| --- | --- | --- | --- |
| `GET /api/wrongway/history` | 조회 허용 | 조회 허용 | 401 |
| `GET /api/events/:id` | 원본 제외 상세 조회 | 원본 포함 상세 조회 | 401 |
| `GET /api/zones` | 조회 허용 | 조회 허용 | 401 |
| `PATCH /api/events/:id/status` | 403 | 상태·사유 저장 허용 | 401 |

권한 허용은 인증된 활성 계정과 유효한 세션을 전제로 하며, 존재하지 않는 이벤트나 잘못된 입력은 별도의 검증 오류를 반환할 수 있습니다.

## 구현 원칙

- 모든 사용자용 보호 API는 `authenticateToken`으로 로그인과 세션 버전을 검증합니다.
- 최고관리자 전용 API는 `authenticateToken` 다음에 `requireRole("SUPER_ADMIN")`를 적용합니다.
- 본인 정보 수정과 비밀번호 변경은 URL의 사용자 ID가 토큰의 사용자 ID와 같은지 서비스 계층에서 검사합니다.
- 프론트엔드는 역할에 맞지 않는 메뉴를 숨길 수 있지만, 실제 보안 검증은 반드시 백엔드에서 수행합니다.
- 이벤트 편집 UI 및 저장 함수의 역할 검사와 백엔드 `PATCH /api/events/:id/status`의 `requireRole("SUPER_ADMIN")`를 함께 유지합니다.
- 앞단 라우터의 공통 권한 검사가 매니저의 조회 요청까지 차단하지 않는지 확인합니다. 상위 등록 순서와 검증 절차는 [백엔드 지침](../ai/backend.md), [테스트 피드백 루프](../ai/testing-feedback-loop.md)를 따릅니다.
