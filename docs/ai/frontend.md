# Frontend

프론트엔드는 기존 사용자 흐름을 깨지 않는 것이 우선이다.

> 최종 업데이트: 2026-08-05

- 기존 라우팅, 상태 관리, API 호출 위치를 따른다.
- 요청하지 않은 화면, 컴포넌트, 디자인 변경은 추가하지 않는다.
- 로딩, 에러, 빈 상태는 기존 패턴이 있으면 재사용한다.
- 하드코딩된 API 주소를 추가하지 않는다.
- 텍스트가 버튼, 카드, 테이블에서 넘치지 않게 한다.
- 가능하면 데스크톱과 모바일 폭을 함께 확인한다.

## 현재 관제 화면 기준

- 메인 `/`은 현재 감지 객체, 경고, 수신 상태, 장비 상태를 빠르게 확인하는 관제 화면으로 유지한다.
- `/statistics`는 일별·주별·월별 통계와 구역별 비교를 표시한다.
- `/events`는 이벤트 이력·필터·상세 확인을 담당한다.
- `/devices`는 구역별 라이다 PC·통합제어보드·VMS 상태를 표시한다.
- 밝은 콘텐츠 영역과 어두운 사이드바를 기본 시각 구조로 사용한다.
- 위험·경고·정상·정보 색상은 상태 의미로만 사용하고 장식으로 남발하지 않는다.

## Mock과 실데이터

- 현재 리디자인 mock은 `src/shared/constants/operationsDashboardData.js`에 둔다.
- mock 데이터를 수정할 때는 실제 API 응답 규격으로 오해하지 않게 주석과 파일명을 유지한다.
- 실데이터 연결 시 `snake_case` 외부 payload를 프론트 내부 `camelCase` 형태로 변환하는 경계를 둔다.
- 페이지 진입만으로 mock 경고 모달을 열지 않는다. 실제 이벤트 수신 또는 명시적인 사용자 작업으로만 연다.
- 실제 API·Redis·WebSocket 연결 전까지 mock 기반 통계를 실제 운영 통계로 표현하지 않는다.
