# 시스템 인프라 및 구매 검토 설계

> 최종 업데이트: 2026-08-31

## 목적

라이다 역주행 방지 시스템의 서버, 카메라, 영상 저장장치 및 LTE 현장 연동에 관한 후속 설계와 구현 작업에서 공통 전제를 제공합니다.

- 팀 공유 및 견적 검토: `docs/specs/system-infrastructure-purchase-review.md`
- 라이다 payload: `docs/specs/lidar-dashboard-payload.md`
- 통합제어보드 연동 TODO: `docs/specs/dashboard-control-board-protocol.md`

## 현재 확정 범위

- 중앙 서버 1대가 회전교차로 2곳과 나들목 2곳을 관제합니다.
- 나들목 2곳은 LTE를 사용하며 이벤트 발생 또는 요청 시에만 영상 자료를 전송합니다.
- 영상분석은 차단기 주변 IR 카메라를 중심으로 검토합니다.
- 차단기는 6개를 기준으로 장비 연동을 검토합니다.
- 카메라는 영상분석 미적용 시 4대, 적용 시 10대를 비교합니다.

## 설계 원칙

- LTE 구간을 상시 영상 스트리밍 또는 상시 중앙 저장 구조로 단정하지 않습니다.
- 영상 저장 용량은 카메라 수, 비트레이트, 보관기간과 RAID 적용 후 사용 가능 용량을 구분합니다.
- 카메라·서버 모델과 가격은 견적 확정 전 코드나 문서의 확정값으로 사용하지 않습니다.
- 영상분석과 차단기 제어는 감지 결과, 관리자 확인, 제어 요청, 장비 응답을 구분해 기록합니다.
- 기존 라이다 이벤트 흐름과 신규 카메라 이벤트 흐름의 책임을 임의로 합치지 않습니다.

## 후속 구현 전 확인사항

- 카메라 RTSP 주소와 인증 방식
- 이벤트 이미지·클립 요청 및 업로드 규격
- LTE 장애 시 재전송과 로컬 임시 저장 정책
- 영상 보관기간과 자동 삭제 정책
- 분석 대상 카메라와 모델 처리량
- 차단기 I/O 규격, 제어 우선권 및 실패 처리
- 운영 OS와 배포 방식

## 변경 영향

- API: 영상 이벤트, 클립 메타데이터, 카메라 상태 API 추가 가능성
- DB: 카메라 장비 정보와 영상 이벤트 메타데이터 설계 가능성
- 환경변수: RTSP, 저장 경로, 보관기간, LTE 업로드 관련 설정 가능성
- 배포: GPU 런타임, 영상 저장 볼륨, 디스크 모니터링 추가 가능성

현재 문서는 설계 전제만 정의하며 API, DB, 배포 설정을 즉시 변경하지 않습니다. 미확정 항목이 결정되면 관련 규격 문서를 먼저 수정한 뒤 구현합니다.
