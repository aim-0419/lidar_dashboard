# 가입 신청 운영 정책

## 현재 정책

- 가입 신청은 로그인하지 않은 사용자도 제출할 수 있으며, 승인 시 기본 권한은 `MANAGER`입니다.
- 가입 신청 전 이메일 인증(아래 "이메일 소유 확인" 참고)을 완료해야 합니다.
- 가입 신청 목록 조회, 승인, 반려는 `SUPER_ADMIN`만 수행할 수 있습니다.
- 가입 신청 상태는 `PENDING`, `APPROVED`, `REJECTED`, `EXPIRED` 중 하나입니다.
- 대기 신청은 최고관리자가 승인 또는 반려합니다.
- `PENDING` 신청은 생성 후 30일이 지나면 자동으로 `EXPIRED` 처리합니다.

## 이메일 소유 확인 (인증코드)

- `POST /signup-requests/email/send-code`로 입력한 이메일에 6자리 인증코드를 발송합니다 (`RESEND_API_KEY` 없으면 실제 발송 대신 서버 로그에만 기록 — [[email-verification-plan]] 참고).
- 코드는 10분간 유효, 시도는 5회까지, 같은 이메일 재발송은 60초 쿨다운입니다. 재발송하면 이전 코드는 자동으로 무효화됩니다(이메일당 가장 최근 코드만 유효).
- `POST /signup-requests/email/verify-code`로 확인하면 30분 동안 "인증된 이메일"로 인정됩니다.
- `POST /signup-requests`(가입 신청 생성)는 신청 저장과 같은 트랜잭션 안에서 인증 레코드를 확인·삭제(1회용 소비)합니다. 30분 안에 가입 신청을 완료하지 않으면 다시 인증해야 합니다.
- 만료됐거나 인증 후 방치된 레코드는 기존 가입 신청 정리 작업(`runSignupRequestMaintenance`, 1시간마다)에서 함께 정리됩니다.
- 전화번호 소유 확인 방식은 아직 미정입니다 (아래 후속 결정 항목).

## 승인 완료 알림 메일

- `PATCH /signup-requests/:id/approve`로 승인이 완료되면, 신청자 이메일로 승인 안내 메일(로그인 링크 포함)을 보냅니다.
- 메일 발송은 fire-and-forget입니다: 발송에 실패해도 승인 자체(계정 생성)는 이미 끝난 뒤이므로 실패 로그만 남기고 넘어갑니다.

## 비밀번호 찾기 (재설정)

- 로그인 화면의 "비밀번호를 잊으셨나요?" → `/forgot-password`. 가입 신청과 동일한 6자리 인증코드 방식입니다.
- `POST /auth/password-reset/send-code`, `/verify-code`, `/confirm` 3단계입니다. `EmailVerification` 테이블을 가입 인증과 공유하되 `purpose="PASSWORD_RESET"`으로 구분합니다.
- **계정 존재 여부를 노출하지 않도록 설계**되어 있습니다: send-code는 계정 존재/쿨다운/메일 발송 성공 여부와 무관하게 항상 같은 응답을 주고, verify-code는 "코드를 요청한 적 없음"과 "코드가 틀림"을 같은 오류로 응답합니다.
- verify-code 성공 시 15분 유효 `resetToken`(JWT)을 발급하고, 이 토큰으로만 confirm에서 새 비밀번호를 설정할 수 있습니다. confirm 성공 시 해당 계정의 기존 로그인 세션(refreshToken)을 모두 무효화합니다.
- resetToken은 JWT라 자체적으로 1회용이 아니지만, verify-code에서 소비(consumedAt 기록)한 `EmailVerification` 레코드가 confirm 성공 시 삭제되므로 같은 resetToken을 재사용할 수 없습니다.

## 중복 방지와 보안

- `users`에 이미 존재하는 `user_id`, `email`, `phone_number`는 가입 신청에 사용할 수 없습니다.
- 대기 중인 가입 신청과 동일한 `user_id`, `email`, `phone_number`도 사용할 수 없습니다.
- `PENDING` 상태에는 DB 부분 unique index를 적용해 동시 요청에도 동일한 ID·이메일·전화번호가 중복 생성되지 않도록 합니다.
- 반려 또는 만료된 가입 신청은 이력으로 보관하며, 동일한 정보로 재신청할 수 있습니다.
- 가입 신청 API는 IP 기준 10분 동안 최대 5회 요청할 수 있습니다.
- 사용자 ID 사용 가능 여부 확인 API는 IP 기준 10분 동안 최대 10회 요청할 수 있습니다.
- 비밀번호는 bcrypt 해시 값으로만 저장합니다.
- 승인 시 비밀번호 해시는 `users.password_hash`로 복사하고, 가입 신청 데이터의 해시 값은 제거합니다.

## 개인정보 보관

- `APPROVED`, `REJECTED`, `EXPIRED` 상태의 신청은 처리 완료 후 90일이 지나면 신청자 개인정보와 반려 사유를 익명화합니다.
- 감사 로그에는 신청 ID와 처리 유형, 처리 시각만 기록하며 신청자 개인정보와 반려 사유는 기록하지 않습니다.

## 목록 조회 기준

- 가입 신청 목록은 생성일 내림차순으로 조회합니다.
- 기본 페이지 크기는 20건이며, 한 번에 최대 100건까지 조회할 수 있습니다.
- 요청한 페이지가 마지막 페이지를 초과하면 마지막 유효 페이지를 반환합니다.

## 후속 결정 항목

- ~~이메일 소유 확인 방식~~ → 인증코드 방식으로 해결 (위 "이메일 소유 확인" 참고)
- 전화번호 소유 확인 방식 (미정)
- ~~승인 완료 알림 메일, 비밀번호 찾기(재설정)~~ → 구현 완료 (위 각 섹션 참고)
