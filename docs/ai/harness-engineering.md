# AI 하네스 엔지니어링 가이드

이 문서는 개발자들이 AI를 부담 없이 활용하되, 프로젝트 기준과 검증 흐름을 놓치지 않기 위한 참고 가이드입니다.

여기서 하네스는 ML 학습 하네스가 아니라, AI와 협업할 때 작업 맥락을 정리하고 결과를 확인하는 공통 습관을 의미합니다.

## 기본 원칙

- AI에게 맡길 작업의 목적과 범위를 먼저 짧게 정리합니다.
- 확정되지 않은 라이다 데이터 규격, API, DB 구조는 확정된 것처럼 다루지 않습니다.
- 코드 변경 전에는 어떤 파일을 볼지, 어떤 파일을 바꿀지 먼저 확인합니다.
- 요청 범위 밖 리팩토링이나 기능 추가는 하지 않습니다.
- 검증하지 못한 내용은 `미검증`이라고 남깁니다.

## 있으면 좋은 정보

AI에게 작업을 맡길 때 아래 정보가 있으면 결과가 더 안정적입니다. 모두 필수는 아닙니다.

```text
작업 목적:
관련 화면 또는 API:
참고하면 좋은 파일:
건드리지 말아야 할 범위:
기대하는 동작:
확인하면 좋은 검증 방법:
```

예:

```text
대시보드 이벤트 리스트를 정리하려고 함.
관련 파일은 DashboardPage와 dashboard.css로 보임.
API 구조는 바꾸지 말고, 밝은 톤으로 가독성만 개선.
가능하면 build까지 확인.
```

## 프론트 작업 시 참고

- 화면 이름과 라우트가 있으면 좋습니다.
- 사용할 API나 mock 데이터 여부가 있으면 좋습니다.
- 로딩, 에러, 데이터 없음 상태가 필요한지 확인합니다.
- 기존 레이아웃과 디자인 톤을 먼저 따릅니다.
- 모바일/데스크톱에서 텍스트가 겹치지 않는지 확인합니다.

## 백엔드 작업 시 참고

- API URL, method, request/response 예시가 있으면 좋습니다.
- 인증이 필요한 API인지 확인합니다.
- Prisma schema 변경이 필요한지 먼저 구분합니다.
- API를 추가하거나 바꾸면 Swagger 문서도 함께 확인합니다.
- mock API와 실제 API를 이름과 설명에서 구분합니다.

## Prisma 작업 시 참고

- DB 변경은 영향 범위가 크므로 migration 실행 전 확인합니다.
- 테이블/컬럼 물리명은 `snake_case`, 코드 필드는 `camelCase`를 기본으로 합니다.
- 실제 라이다 규격이 없을 때는 너무 세부적인 컬럼을 먼저 확정하지 않습니다.
- 필요하면 `rawPayload` 같은 JSON 필드로 임시 수용합니다.

## Swagger 작업 시 참고

- 구현된 API와 문서가 다르면 프론트 개발자가 헷갈립니다.
- request body, response, 에러 예시가 있으면 좋습니다.
- 아직 구현하지 않은 API는 확정된 것처럼 문서화하지 않습니다.
- mock API는 summary나 description에 mock임을 적습니다.

## 라이다/mock 작업 시 참고

- 조대측 라이다 규격은 아직 확정되지 않았습니다.
- mock, demo, 임시 개발용 데이터를 실제 규격처럼 설명하지 않습니다.
- 실제 연동 전까지는 adapter로 교체 가능하게 분리합니다.
- 필드 의미가 불확실하면 `확인 필요`라고 남깁니다.

## 주의가 필요한 작업

- 패키지 설치, DB migration, Docker 설정 변경은 영향 범위가 크므로 작업 전 확인합니다.
- 인증/권한 로직 변경은 기존 로그인 흐름과 보호 라우트에 영향이 있는지 확인합니다.
- AI가 만든 코드는 담당 개발자가 최종 리뷰합니다.
- 조대측 라이다 실제 데이터 예시를 받으면 mock 기준으로 만든 API, DB, adapter 구조를 다시 점검합니다.
- 컨벤션과 실제 코드가 달라지면 문서도 함께 수정합니다.

## 결과 확인

AI 작업 결과를 받을 때는 아래 정도만 확인하면 충분합니다.

```text
수정 파일:
변경 내용:
검증 여부:
미검증 또는 주의할 점:
```

특히 실패한 검증, 실행하지 못한 테스트, 추측으로 작성한 내용이 숨겨지지 않았는지 확인합니다.

## 작업 완료 후 확인

개발이 끝나면 가능한 범위에서 빌드, 테스트, 린트, 서버 실행 확인 중 적절한 검증을 수행합니다.

예:

```text
프론트 변경: npm --prefix dashboard/dashboard-web run lint
프론트 빌드: npm --prefix dashboard/dashboard-web run build
백엔드 변경: npm --prefix dashboard/server start
Docker 변경: docker compose up --build
```

검증 명령을 실행했다면 결과를 함께 남깁니다. 실행하지 못한 검증은 `미검증`으로 표시하고 이유를 적습니다.
