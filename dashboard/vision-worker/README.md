# Vision worker

## 카메라 영상 주소 등록 (2026-09-29)

카메라 선택 후 영상 입력을 테스트 영상 또는 RTSP 카메라로 설정한다.
RTSP 주소는 나중에 입력할 수 있으며 기본값은 테스트 영상이다.
주소 입력칸을 비우고 저장하면 기존 주소를 유지한다. 새 주소를 입력하면 교체한다.
카메라 연결 실패 시 오류를 표시하고 재접속한다. 테스트 영상으로 자동 대체하지 않는다.
편집 화면은 선택된 카메라의 원본 프레임을 약 200ms 간격으로 조회하며,
원본 종횡비를 유지한다. 실제 갱신 속도는 추론 처리 속도에 따라 달라진다.
설정 저장 전까지 분석에는 기존 ROI를 사용한다.

영상 설정은 /data/rois/sources/camera-N.json에 저장된다.
조회 API는 입력 모드와 주소 등록 여부만 반환하며 주소/비밀번호는 반환하지 않는다.
파일 자체는 암호화되지 않으므로 Docker 볼륨 접근 권한과 백업을 제한해야 한다.
OpenCV/FFmpeg의 원문 로그는 접속정보 노출을 방지하기 위해 억제한다.
현재 서비스에는 API 인증이 없으므로 신뢰하는 로컬 개발 환경에서만 사용한다.
실제 운영 카메라 자격증명 등록 전 인증·HTTPS·비밀정보 저장 정책을 별도로 적용해야 한다.
실카메라 RTSP 연결 및 장시간 지연/재접속 성능은 아직 미검증이다.

## 카메라별 ROI 설정 (2026-09-28)

- 카메라 1~6은 독립적인 설정을 가진다. 기본 영상 입력은 SC10 테스트 자산이며,
  동시에 6개 영상을 분석하는 구성이 아니라 선택된 카메라 설정 하나를 시험한다.
- 카메라 선택 후 ROI 편집을 누르면 현재 원본 영상을 갱신하면서 편집한다. 백그라운드 분석은 계속된다.
- 영역 추가/삭제, 이름 변경, 흰색 꼭짓점 드래그, 초록색 방향 끝점 드래그를 지원한다.
- 저장 및 적용은 선택된 카메라의 설정을 저장하고 활성 분석의 추적 ID/이력을 초기화한다.
  취소는 편집 내용을 버린다. 다시 편집을 열면 서버에 저장된 설정을 불러온다.
- 신규 카메라는 빈 ROI로 시작한다. SC10 예시 불러오기는 초안만 변경하며 저장 전에는 적용되지 않는다.
- 좌표와 방향 벡터는 영상 너비/높이에 대한 정규화 좌표이다. 추론 시 실제 해상도로 변환한다.
- 서버에서 좌표 범위, 면적, 자기 교차, 중복 이름/꼭짓점, 유효 방향을 검사한다.
- 파일은 /data/rois/camera-1.json 형태로 저장된다. Docker의 vision_roi_settings 볼륨에 유지되며
  컨테이너 재생성 후에도 보존된다. docker compose down -v는 이 설정도 삭제하므로 주의한다.
- GET/PUT /cameras/{camera-1..camera-6}/rois, GET /reference-rois 사용.
  저장 형식: {"rois":[{"name":"Lane1","polygon":[[0.1,0.1],[0.8,0.1],[0.8,0.8]],"direction":[0.15,0]}]}.
- 테스트 서비스의 설정은 접속자끼리 공유된다. 동시 편집은 마지막 저장이 우선한다.
  운영용 인증/권한은 별도 구현 범위이며 실제 RTSP 연결은 현장 검증이 필요하다.

## 영상 기반 역주행 테스트 (2026-09-28)

프로젝트 루트에서 `docker compose up --build` 실행 후 로그인하여
`http://localhost:5173/vision-test` 또는 사이드바의 비전 테스트 메뉴로 이동한다.
테스트 경로는 Vite 개발 환경에서만 등록한다. 실장비 제어와 이벤트 DB 저장은 하지 않는다.

- 정상 방향: SC10 영상에 맞춘 구역별 정상 방향을 사용한다.
- 역방향: 각 구역의 정상 방향 벡터를 반전한다. 영상 역재생이 아니다.
- 방향 선택 또는 재시작 버튼 클릭 시 영상, 추적 ID, 감지 이력을 초기화한다.
- 실제 차량 박스, ID, 궤적, ROI, 방향 화살표를 표시한다.
- 초록은 정상/판정 대기, 노랑은 역주행 후보, 빨강은 역주행 확정이다.
- 확정 기준은 원본 README의 SC10 역방향 시각화 예시처럼 연속 3프레임으로 설정한다.
  정상/역방향 모두 같은 기준을 사용하며 운영 임계값은 아니다.
- 원본 코드처럼 한번 확정된 역주행 상태는 해당 ID에서 유지한다.
- 영상 끝에서는 추적 상태와 이력을 초기화하고 반복한다.
- CPU 처리 속도에 따라 원본보다 느릴 수 있으며 프레임을 건너뛰지 않는다.

### 원본 프로젝트와 자산

`vision_worker/reference/`는 로컬 `CV-Wrongway-Detection`의 config, detector,
tracking, wrongway, visualization 코드를 가져온 것이다. 패키지 import 경로만 수정하였다.
SC10 ROI 좌표, YOLO11s + ByteTrack, 이동 궤적과 방향 비교, 표시 방식을 재사용한다.
기존 데모 서버의 감지 코드나 합성 좌표를 사용하지 않는다.

로컬 자산은 용량 때문에 Git에서 제외한다. 다른 PC에서는 빌드 전에 다음 파일을 준비해야 한다.

| 현재 저장 위치 | 원본 파일 |
| --- | --- |
| `assets/sc10.mp4` | `CV-Wrongway-Detection/videos/Sc10_Traffic roundabout_static camera.mp4` |
| `assets/yolo11s.pt` | `CV-Wrongway-Detection/yolo11s.pt` |

최초 빌드에는 CPU PyTorch 설치 시간이 필요하다. 기존 저장소의 Python 의존성 목록을
재사용하며 호스트에 패키지를 설치하지 않는다.
개발용 HTTP API는 별도 인증이 없으므로 신뢰할 수 있는 개발망에서만 사용한다.
운영 배포에 테스트 서비스와 Vite 프록시를 포함하지 않는다.

### 검증 명령

```sh
docker compose exec vision-worker python -m unittest discover -s tests -v
```

`/health`는 서비스 생존 여부, `/state`의 error/frame은 영상 처리 상태이다.
`POST /settings` 요청은 `{"direction":"normal"}` 또는
`{"direction":"reverse"}`만 허용한다.

## 독립 판정 모듈

`core.py`, `worker.py`, `detection.py`는 앞서 작성한 제어 인터페이스 모듈이며,
이번 영상 테스트에서는 호출하지 않는다. 테스트는 원본 CV 프로젝트의 감지 흐름만 실행한다.
라이다 객체 ID를 연결하지 않는다.

RTSP 장시간 안정화 검증, 실제 제어보드 통신, 안전 인터록, 대시보드 이벤트 전송,
YOLOX 및 DX-M1 NPU 적용은 별도 통합 범위이다.
실제 카메라, 야간 환경, 장시간 운영 및 현장 정확도는 미검증이다.
테스트 성공은 차단기 운영 승인이나 현장 안전 검증을 의미하지 않는다.
